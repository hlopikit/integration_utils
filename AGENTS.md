# AGENTS.md

Инструкции для ИИ-агентов по выбору методов обращения к Bitrix24 API в `integration_utils`.

## `call_api_method`

Самый простой способ обращения к Bitrix24 REST API.

Что делает:

- выполняет 1 HTTP-запрос в API Битрикс24 по указанному REST-методу;
- возвращает ответ ровно в том виде, в котором его отдал API Битрикс24;
- обычно в успешном ответе есть ключи `result` и `time`;
- в подавляющем большинстве случаев должен успевать отработать за стандартный timeout 10 секунд.

Когда использовать:

- нужно разово выполнить CRUD-действие с одним объектом одной сущности;
- нужно получить один объект по ID;
- нужно вызвать метод, который не является списочным;
- нужна простая операция без batch и без постраничной выборки.

Пример:

```python
response = but.call_api_method("crm.deal.get", params={"id": deal_id})
deal = response["result"]
```

## `batch_api_call`

Используется для выполнения нескольких REST-команд через метод Битрикс24 `batch`.

Документация Битрикс24:

- `batch`: https://apidocs.bitrix24.com/api-reference/how-to-call-rest-api/batch.html

Что делает:

- принимает набор REST-команд;
- под капотом разбивает команды на чанки по 50 штук;
- для каждых 50 команд делает 1 запрос в Битрикс24;
- возвращает общий результат batch-вызовов.

Почему 50:

- `batch` в Битрикс24 выполняет до 50 команд за один REST-запрос;
- если команд больше 50, helper сам разобьет их на несколько запросов.

Когда использовать:

- нужно выполнить много независимых операций;
- нужно получить несколько разных объектов;
- нужно массово вызвать один и тот же метод по разным ID;
- нужно уменьшить количество HTTP-запросов к Битрикс24.

Когда не использовать:

- нужно получить весь список сущностей с пагинацией - для этого обычно лучше `call_list_method`;
- команды требуют сложной обработки результата после каждой отдельной операции;
- повторный запуск batch может создать дубли, а защиты от дублей нет.

### Формат команд

Можно передавать команды списком:

```python
batch = but.batch_api_call([
    ("user.current", {}),
    ("app.info", {}),
])
```

Можно передавать команды с ключами:

```python
batch = but.batch_api_call({
    "current_user": ("user.current", {}),
    "app": ("app.info", {}),
})
```

Ключи нужны, когда в ответе удобно доставать результат по своему имени:

```python
current_user = batch["result"]["result"]["current_user"]
app_info = batch["result"]["result"]["app"]
```

Если свои ключи не нужны, можно передавать список.

### Списочные методы внутри batch

Списочный REST-метод - это метод, который возвращает часть списка и данные пагинации (`total`, `next` или аналогичный механизм).

Один вызов списочного метода обычно возвращает до 50 элементов. Через один batch-запрос можно выполнить 50 таких команд, то есть получить до 2500 элементов одной сущности за один HTTP-запрос к `batch`.

Если нужно получить весь список, обычно не надо собирать такой batch вручную. Используй `call_list_method`, потому что он уже знает, как работать с пагинацией.

### Зависимые команды

В Bitrix24 batch команды могут ссылаться на результаты предыдущих команд через синтаксис `$result`.

Пример идеи:

```python
batch = but.batch_api_call({
    "deal": ("crm.deal.get", {"id": deal_id}),
    "contact": ("crm.contact.get", {"id": "$result[deal][CONTACT_ID]"}),
})
```

Такой подход нужен, когда вторая команда зависит от результата первой. Если зависимости нет, лучше держать команды независимыми.

## RetrySettings

Если нужно повторять REST-вызов при временных ошибках, передавай `retry_settings` в метод токена:

```python
response = but.call_api_method(
    "crm.deal.get",
    params={"id": deal_id},
    retry_settings=but.RetrySettings(
        attempts=3,
        delay=1,
        exceptions=(BitrixApiException,),
        should_retry=lambda exc: exc.is_not_logic_error,
    ),
)
```

Нюансы:

- `attempts` включает первую попытку;
- логические ошибки Битрикс24 ретраить не нужно;
- для `BitrixApiException` обычно ретраятся только ошибки с `exc.is_not_logic_error`;
- retry для write-методов опасен, если повтор может создать дубль или повторить действие;
- если retry нужен в `call_list_method` или `call_list_fast`, он должен просто пробрасываться до `call_api_method` / `batch_api_call`.
