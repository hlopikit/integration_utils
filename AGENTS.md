# AGENTS.md

Краткие правила для ИИ-агентов по работе с Bitrix24 REST API через `integration_utils`.

## Как выбрать helper

Используй `call_api_method`, когда нужен один REST-вызов: получить объект по ID, создать один объект, обновить один объект, вызвать служебный метод или получить первую страницу списочного метода. Метод возвращает сырой JSON-ответ Bitrix24, обычно с ключами `result` и `time`.

```python
response = but.call_api_method("crm.deal.get", params={"id": deal_id})
deal = response["result"]
```

Используй `call_list_method`, когда нужно получить список по методу с пагинацией. Helper сам делает первый запрос, смотрит `next`/`total`, добирает остальные страницы через batch и возвращает собранный список. Если нужен полный `total`, передай `return_total=True`.

```python
deals = but.call_list_method(
    "crm.deal.list",
    fields={"filter": {"CATEGORY_ID": 0}, "select": ["ID", "TITLE"]},
    limit=500,
)
```

Используй `call_list_fast`, когда нужно быстро читать большой список и метод уже описан в справочниках `call_list_fast`: `METHOD_TO_ORDER`, `METHOD_TO_FILTER`, `METHOD_TO_ID`. Он работает через batch, `start=-1` и фильтр по ID. Если метода нет в справочниках, не добавляй его наугад: сначала проверь, что API-метод поддерживает сортировку, фильтр по ID и ожидаемый формат результата.

```python
for deal in but.call_list_fast("crm.deal.list", params={"select": ["ID", "TITLE"]}):
    ...
```

Используй `batch_api_call`, когда нужно выполнить несколько REST-команд и сократить число HTTP-запросов. В Bitrix24 один batch содержит максимум 50 подзапросов; helper режет команды на чанки по `chunk_size`.

```python
batch = but.batch_api_call([
    ("user.current", {}),
    ("app.info", {}),
])
```

Если результат надо доставать по понятному ключу, передавай именованные команды тройками:

```python
batch = but.batch_api_call([
    ("current_user", "user.current", {}),
    ("app", "app.info", {}),
])

current_user = batch["current_user"]["result"]
```

`batch_api_call` возвращает плоский `BatchResultDict`: у каждого ключа есть `result`, `error`, `time`, `total`, `next`. Ошибки отдельных подзапросов проверяй через `batch.all_ok`, `batch.errors` или `batch.iter_errors()`.

## Нюансы batch Bitrix24

В batch можно делать независимые команды или связанные команды. Связанные команды используют результат предыдущего подзапроса через `$result[ключ][поле]`.

```python
batch = but.batch_api_call([
    ("deal", "crm.deal.get", {"id": deal_id}),
    ("contact", "crm.contact.get", {"id": "$result[deal][CONTACT_ID]"}),
])
```

Связанные команды уместны, когда всю цепочку можно считать одной бизнес-операцией и частичное выполнение не создаст неконсистентность. Например, получить сделку и связанный контакт нормально. Пачка `add/update/delete`, которую опасно повторить, требует отдельной оценки.

`halt=0` означает, что Bitrix24 продолжит выполнять подзапросы после ошибки и положит ошибки в `result_error`. `halt=1` останавливает выполнение следующих подзапросов в batch после ошибки.

Не вкладывай `batch` внутрь `batch`: в Bitrix24 REST это запрещено.

## Списочные методы

Списочный REST-метод возвращает часть списка и признаки пагинации, обычно `total` и `next`. Один вызов обычно возвращает до 50 элементов. Если вручную вызываешь списочный метод через `call_api_method`, следующую страницу надо запрашивать со `start`, равным значению `next`.

Для полного списка не пиши ручной цикл с `start`, если нет особой причины. Обычно правильнее `call_list_method`.

Через batch можно запросить 50 страниц по 50 элементов и получить до 2500 элементов за один HTTP-запрос к `batch`, но это не отменяет лимиты ресурсоемкости методов.

## Лимиты и operating

Bitrix24 ограничивает REST по времени выполнения запроса, интенсивности запросов и ресурсоемкости методов. Batch уменьшает число HTTP-запросов, но не отменяет лимиты вложенных методов.

При превышении интенсивности запросов Bitrix24 может вернуть `503 QUERY_LIMIT_EXCEEDED`. Если превышен лимит ресурсоемкости метода, возможен `429 OPERATION_TIME_LIMIT`; в ответах REST смотри `time.operating` и `time.operating_reset_at`.

## RetrySettings

Retry передается через `retry_settings` в методы токена. Используй его только для временных ошибок и только когда повтор безопасен.

```python
response = but.call_api_method(
    "crm.deal.get",
    params={"id": deal_id},
    retry_settings=but.RetrySettings(
        attempts=3,
        delay=1,
        exceptions=(BitrixApiException,),
        should_retry=lambda exc: exc.is_not_logic_error,
    ),
)
```

Правила:

- `attempts` включает первую попытку;
- логические ошибки Bitrix24 не ретраить;
- для `BitrixApiException` проверяй `exc.is_not_logic_error`;
- write-методы ретраить только при идемпотентности или защите от дублей;
- retry batch повторяет batch-вызов целиком, а не один упавший подзапрос.

## Что не делать

- Не писать ручную пагинацию, если подходит `call_list_method`.
- Не делать `call_api_method` в цикле, если запросы можно объединить через `batch_api_call`.
- Не использовать `call_list_fast` для метода, которого нет в его справочниках.
- Не кодировать параметры REST-запросов вручную перед передачей в helper.
- Не подменять ошибочный ответ API пустым значением без явного бизнес-правила.

## Ошибки

Не подавляй исключения REST API без явного бизнес-правила. Если обработка ошибки допустима, оставь в коде понятное условие, почему именно этот случай можно игнорировать или заменить дефолтным значением.

Если ошибка пришла внутри batch-подзапроса, проверяй `BatchResultDict`, а не только исключения Python.
