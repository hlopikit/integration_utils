# Параметры Django views

## get_params_from_sources

`get_params_from_sources` собирает `request.its_params` из JSON тела запроса,
POST и GET (приоритет GET → POST → JSON). Строки из GET и POST сначала
декодируются через `json.loads`, если это возможно. Декоратор сбора параметров
должен стоять **над** декораторами чтения параметров.

## expect_param / expect_param_api

`expect_param(param, from_='its_params', coerce=None, default=missing,
as_=None, err=HttpResponseBadRequest)` читает один ключ. Отсутствующий
обязательный ключ даёт HTTP 400. `default` используется только при отсутствии
ключа. `coerce` вызывается только для переданного значения; он может быть
функцией/типом или парой `(функция, название типа для ошибки)`. `as_` задаёт
имя аргумента view. `from_` может быть `its_params`, `GET` или `POST`.
`expect_param_api` имеет те же параметры, кроме `err`, и возвращает JSON
`{"error": "..."}` с HTTP 400. `expect_flag` и `expect_flag_api` — сокращения
для булевых параметров; `null=True` разрешает пустое/null значение.

Эти декораторы подходят, когда требуется собственная функция `coerce`,
переименование аргумента или проверка одного параметра за раз.

## expect_typed_params

`expect_typed_params(source='its_params', api=False)` обрабатывает все
аннотированные аргументы view одним декоратором. Он использует `cattrs` для
рекурсивного преобразования. Для него требуется `cattrs>=24.1.0`; остальные
декораторы из модуля работают без этой зависимости. Неаннотированные параметры,
`request`, а также параметры сигнатуры `*args` и `**kwargs` пропускаются.
Аннотированные positional-only параметры (слева от `/`) не поддерживаются:
при загрузке view декоратор вызывает `TypeError` с именем такого параметра.
Аргумент, уже переданный Django позиционно или по имени, не читается из запроса.
Необязательность определяется наличием `default` в сигнатуре: `Optional[T]`
без `default` остаётся обязательным параметром. `source` может быть
`its_params`, `GET` или `POST`.

```python
from integration_utils.iu_get_params import get_params_from_sources
from integration_utils.iu_get_params.decorators import expect_typed_params

@get_params_from_sources
@expect_typed_params(api=True)
def save_items(request, items: list[dict[str, int]], page: int = 0):
    ...
```

При отсутствии обязательного ключа возвращается HTTP 400. Ошибки приведения
включают имя аргумента и путь к элементу, например `items[1]['id']`.
`api=False` возвращает обычный HTTP 400, `api=True` — JSON
`{"error": "..."}` с HTTP 400. Для прямого `GET`/`POST` строковые значения
также предварительно разбираются как JSON.

### Поддерживаемые типы

Декоратор поддерживает следующие типы параметров:

| Тип | Назначение / пример |
| --- | --- |
| `str`, `int`, `float`, `bool` | Строки, числа и флаги |
| `list[T]` | Список, например `list[int]` |
| `dict[str, T]` | Объект со строковыми ключами, например `dict[str, int]` |
| `Optional[T]` / `T \| None` | Значение типа `T` либо `None` |
| `Literal[...]` | Фиксированные значения, например `Literal['asc', 'desc']` |

Контейнеры и nullable-типы можно вкладывать друг в друга:
`list[dict[str, int]]`, `list[str | None]`, `dict[str, list[int]]`.
Объединение `int | str` не поддерживается.

Для `Literal[...]` должны совпадать и значение, и его тип: например, `True`
не считается допустимым значением для `Literal[1]`. Несовпадение даёт HTTP 400.

Для `bool` поддерживаются `true`/`false`, `1`/`0` и соответствующие
строковые формы. Строковые целые и дробные числа преобразуются в `int` и
`float`, если полностью соответствуют формату числа. Для `int` не принимаются
`bool` и дробные числа, для `float` — `bool`, `NaN` и бесконечность.

Значение для `str` должно быть строкой, для `list[T]` — списком, для
`dict[str, T]` — словарём. Эти требования действуют и для вложенных значений.
Например, строка `"123"` не преобразуется в `[1, 2, 3]`, а число `1.9` — в `1`:
такие значения приводят к HTTP 400. Список в `GET`/`POST` передаётся
JSON-массивом, например `?ids=[1,2,3]`. Чтобы передать похожее на число значение
как `str`, нужны JSON-кавычки, например `?code="123"`.

### Отсутствие параметра, null и пустая строка

`default` применяется **только** когда ключ отсутствует. Он приводится к
аннотированному типу при создании декоратора; некорректный `default` вызывает
ошибку при загрузке view. Изменяемый `default` копируется на каждый запрос.

- `null` становится `None`, если тип допускает `None`; иначе — HTTP 400.
- `""` остаётся пустой строкой для `str` и `str | None`; для `int | None` — ошибка.
- `default` подставляется только при отсутствии ключа, а не вместо `null` или `""`.

Правила преобразования действуют и для вложенных элементов.

| Объявление | Ключ отсутствует | Передан `null` | Передана пустая строка |
| --- | --- | --- | --- |
| `name: str` | HTTP 400 | HTTP 400 | `""` |
| `name: str = ''` | `""` | HTTP 400 | `""` |
| `name: str \| None` | HTTP 400 | `None` | `""` |
| `name: str \| None = None` | `None` | `None` | `""` |
| `name: str \| None = 'guest'` | `'guest'` | `None` | `""` |

Типизация не заменяет прикладные ограничения вроде положительного числа или
списка допустимых идентификаторов: их проверяет сама view либо отдельная
функция `coerce` в `expect_param`.
