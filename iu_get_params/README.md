# Параметры Django views

## get_params_from_sources

`get_params_from_sources` собирает `request.its_params` из JSON тела запроса,
POST и GET (приоритет GET → POST → JSON). Строки из GET и POST сначала
декодируются через `json.loads`, если это возможно. Для обратной совместимости
это поведение `request.its_params` не меняется. Исходные строки GET/POST также
сохраняются в `request.its_raw_params`; их автоматически использует
`expect_typed_params`. Декоратор сбора параметров должен стоять **над**
декораторами чтения параметров.

## expect_param / expect_param_api

`expect_param(param, from_='its_params', coerce=None, default=missing,
as_=None, err=HttpResponseBadRequest)` читает один ключ. Отсутствующий
обязательный ключ даёт HTTP 400. `default` используется только при отсутствии
ключа. `coerce` вызывается только для переданного значения; он может быть
функцией/типом или парой `(функция, название типа для ошибки)`. `as_` задаёт
имя аргумента view. `from_` может быть `its_params`, `GET` или `POST`.
`expect_param_api` имеет те же параметры, кроме `err`, и возвращает JSON
`{"error": "..."}` с HTTP 400. `expect_flag` и `expect_flag_api` — сокращения
для булевых параметров; `null=True` разрешает пустое/null значение.

Эти декораторы подходят, когда требуется собственная функция `coerce`,
переименование аргумента или проверка одного параметра за раз.

## expect_typed_params

`expect_typed_params(source='its_params', api=False)` обрабатывает все
аннотированные аргументы view одним декоратором. Он использует `cattrs` для
рекурсивного преобразования. Для него требуется `cattrs>=24.1.0`; остальные
декораторы из модуля работают без этой зависимости. Неаннотированные параметры,
`request`, а также параметры сигнатуры `*args` и `**kwargs` пропускаются.
Обрабатываются параметры, которые можно передать по имени.
Аннотированный positional-only параметр (слева от `/`) не поддерживается и
вызывает `TypeError` при загрузке view.
Аргументы, переданные Django позиционно или по имени (например, из URL),
имеют приоритет над параметрами запроса и тоже преобразуются по аннотации.
Например, `item_id='12'` для `item_id: int` станет `12`.
Необязательность определяется наличием `default` в сигнатуре: `Optional[T]`
без `default` остаётся обязательным параметром. `source` может быть
`its_params`, `GET` или `POST`.

```python
from integration_utils.iu_get_params import get_params_from_sources
from integration_utils.iu_get_params.decorators import expect_typed_params

@get_params_from_sources
@expect_typed_params(api=True)
def save_items(request, items: list[dict[str, int]], page: int = 0):
    ...
```

При отсутствии обязательного ключа возвращается HTTP 400. Ошибки приведения
включают имя аргумента и путь к элементу, например `items[1]['id']`.
`api=False` возвращает обычный HTTP 400, `api=True` — JSON
`{"error": "..."}` с HTTP 400.

Строки из GET и POST интерпретируются с учётом аннотации. Для `str` исходный
текст сохраняется без изменений. Для `int`, `float` и `bool` текст передаётся
соответствующему строгому преобразователю. Для `list[T]` и `dict[K, V]`
значение сначала разбирается как JSON. Значения из JSON-тела уже имеют JSON-тип
и не проходят повторный разбор.

### Поддерживаемые типы

| Тип | Что принимается |
| --- | --- |
| `int` | Целые числа, `float` без дробной части и строки вроде `"12"`, `"12.0"` |
| `float` | Конечные числа `int`/`float` и числовые строки, например `"12.5"` |
| `str` | Строки и числа `int`/`float`: `123` становится `"123"` |
| `bool` | `True`, `False`, `1`, `0`, `1.0`, `0.0` и строки `"true"`, `"false"`, `"1"`, `"0"` |
| `list[T]` | `list`, `tuple`, `range` и другие спископодобные `Sequence` |
| `dict[str, T]` | Словари и другие `Mapping`; ключи и значения преобразуются по аннотациям |
| `Optional[T]` / `T \| None` | Значение типа `T` либо `None` |
| `Union[T1, T2]` / `T1 \| T2` | Значение, подходящее хотя бы одному из перечисленных типов |
| `Literal[...]` | Значение из перечисленных с совпадающим типом, например `'asc'` для `Literal['asc', 'desc']` |

Преобразование работает рекурсивно: `list[dict[str, int]]`,
`list[str | None]`, `dict[str, list[int]]`.
Текстовые и бинарные последовательности `str`, `bytes`, `bytearray` и
`memoryview` не принимаются как `list[T]`.

Для `Union` сначала проверяются варианты, которым исходное значение уже
соответствует по типу. Поэтому строка `"123"` для `Union[int, str]` остаётся
строкой, а число `123` остаётся числом. Если прямого совпадения нет, варианты
преобразования проверяются в порядке их объявления в `Union`.

Для `Union` строка GET/POST сначала проверяется как JSON. Разобранное значение
передаётся только нестроковым вариантам; если ни один из них не подходит,
варианты проверяются на исходном тексте. Поэтому для `int | str` значение
`123` становится числом, `"123"` — строкой без JSON-кавычек, а `hello` остаётся
строкой. Аналогично, для `bool | str` значение `true` становится `True`, а
`"true"` — строкой. Для `str | None` значение `null` становится `None`, а
`"null"` — строкой.

Список в GET/POST передаётся JSON-массивом, например `?ids=[1,2,3]`, а словарь —
JSON-объектом. Обычный `str` JSON-разбор не проходит: значения `true`, `null`,
`1e3` и даже текст `"hello"` с кавычками попадают во view без изменений.

### Отсутствие параметра, null и пустая строка

`default` применяется **только** когда ключ отсутствует. Он приводится к
аннотированному типу при создании декоратора; некорректный `default` вызывает
ошибку при загрузке view. Изменяемый `default` копируется на каждый запрос.

- JSON `null` становится `None` для `Optional[T]` / `T | None`. То же правило
  действует для не заключённого в кавычки `null` из GET/POST.
- `""` остаётся пустой строкой для `str` и `str | None`.

Правила преобразования действуют и для вложенных элементов.

| Объявление | Ключ отсутствует | JSON `null` | GET/POST `null` | Пустая строка |
| --- | --- | --- | --- | --- |
| `name: str` | HTTP 400 | HTTP 400 | `"null"` | `""` |
| `name: str = ''` | `""` | HTTP 400 | `"null"` | `""` |
| `name: str \| None` | HTTP 400 | `None` | `None` | `""` |
| `name: str \| None = None` | `None` | `None` | `None` | `""` |
| `name: str \| None = 'guest'` | `'guest'` | `None` | `None` | `""` |

Прикладные ограничения, например положительное число или допустимые
идентификаторы, проверяет view либо функция `coerce` в `expect_param`.
